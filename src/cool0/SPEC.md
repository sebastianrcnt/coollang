# cool0 명세

**이 명세는 동결이다.** cool0 는 부트스트랩 전용 언어이며 기능을 더하지 않는다.
부족한 것은 cool1 이 채운다.

타깃은 **wasm 1.0 (MVP)** 하나. 임포트 없음, WASI 없음, I/O 없음.

---

## 1. 원칙

cool0 는 **컴파일러를 실수 없이 손으로 구현할 수 있는 최소 언어**다. 그 외의
목표는 없다.

- **안전 규칙은 별칭(aliasing)과 가변성만.** 소유권·수명·자동 해제(RAII)가 없다.
  cool0 컴파일러는 순수 함수라 한 번 돌고 호스트가 메모리를 회수하므로 **아무것도
  해제하지 않는다.** 그래서 소유권 추적이 필요 없다.
- **기본 불변.** `mut` 으로만 연다. 규칙 하나가 `let`/`&`/`[]` 전부에 적용된다.
- **숨은 흐름 없음.** 암묵 변환 없음, 연산자 오버로딩 없음, 소멸자 없음, 예외 없음.
- **같은 일을 하는 기능을 둘 두지 않는다.** 루프는 `for` 하나다.

## 2. 어휘

소스는 **ASCII 전용**이다 (`0x09 0x0A 0x0D`, `0x20`–`0x7E`). 그 밖의 바이트는 오류.

- 주석 `// 줄 끝까지`
- 식별자 `[A-Za-z_][A-Za-z0-9_]*`
- 정수 리터럴 `123`, `0xFF`, `0b1010`. `_` 를 자리 구분에 쓸 수 있다. 값은 32비트에
  들어가야 한다 (`0`–`0xFFFFFFFF`). **타입은 쓰이는 자리에서 받는다** — `i32` 나 `u32`
  중 문맥이 요구하는 쪽이고, 요구가 없으면 `i32` 다. 이것이 유일한 추론이다
- 문자 리터럴 `'a'`. 탈출은 `\n \t \r \0 \\ \'` 뿐. 값은 `u32`
- 문자열 리터럴 `"..."`. 탈출은 위와 같고 `\"` 추가. 타입은 `[]u8`
- `true` `false`

**키워드** — 전부 17개:

```
fn struct enum const let mut if else for break continue
return match unsafe as true false
```

`_` 는 match 의 와일드카드 자리에서만 특별하다.

## 3. 타입

| | |
|---|---|
| `i32` | 부호 있는 32비트 |
| `u32` | 부호 없는 32비트 |
| `bool` | `true`/`false`. 정수가 아니다 — 조건 자리에 정수를 쓸 수 없다 |
| `u8` | **저장 전용.** 슬라이스 원소와 struct 필드로만. 읽으면 `u32`, 쓸 때 잘린다. `u8` 지역변수도 `u8` 산술도 없다 |
| `[]T` `[]mut T` | 슬라이스. (포인터 `u32`, 길이 `u32`) 8바이트 |
| `&T` `&mut T` | 대여. §7 |
| `*T` | 생 포인터. 역참조는 `unsafe` 안에서만 |
| struct | §4 |
| enum | §4 |

**메모리에 놓일 때의 크기와 정렬:**

| | 크기 | 정렬 |
|---|---|---|
| `i32` `u32` | 4 | 4 |
| `bool` | 1 | 1. 값은 `0` 또는 `1` |
| `u8` | 1 | 1 |
| `[]T` `[]mut T` | 8 | 4. `(ptr, len)` 순서 |
| `&T` `&mut T` `*T` | 4 | 4 |

슬라이스의 길이는 **`s.len`** 으로 읽는다. `u32` 이고 읽기 전용이다. 이것이 슬라이스의
유일한 필드다.

**암묵 변환은 없다.** `as` 로만 바꾼다. `as` 는 `i32`↔`u32`↔`*T` 사이의 비트 재해석이며
값을 바꾸지 않는다. `bool` 은 `as` 의 대상이 아니다.

정수 산술은 **랩어라운드**한다 (2의 보수). 0 나눗셈과 부호 있는 나눗셈 오버플로는
트랩이다 — wasm 이 그렇게 한다.

집합체(struct·enum)는 **값으로 전달하거나 반환할 수 없다.** `&T`/`&mut T` 로 넘기거나
슬라이스에 담는다. 지역변수로 두는 것과 리터럴로 만드는 것은 된다.

**슬라이스는 반환할 수 없다.** wasm 1.0 은 결과가 하나인데 슬라이스는 값이 둘이다.
인자로 넘기는 것은 된다 — `i32` 둘로 펼친다. 대여도 반환할 수 없다 (§7).

**지역변수는 `u8` 도 대여 타입도 될 수 없다.** `u8` 은 저장 전용이고, 대여는 인자
자리에서만 산다.

## 4. 선언

```
fn name(p: T, q: T) -> T { ... }     // -> 를 생략하면 반환값 없음
struct Name { a: T, b: T }
enum Name { A, B(T), C(T, T) }
const NAME: T = <상수식>;
```

**최상위 선언은 순서에 상관없다.** 컴파일러는 2패스다 — 먼저 모든 선언을 모으고
그다음 본문을 컴파일한다. 상호 재귀가 그냥 된다.

**배치는 결정적이다.** struct 필드는 선언 순서대로, 각자 자기 크기에 정렬되고,
struct 의 정렬은 필드 정렬의 최대값, 크기는 그 배수로 올림한다. enum 은
`태그(u32) + 페이로드 슬롯` 이며 슬롯 크기는 배리언트 페이로드 크기의 최대값이다.
페이로드 슬롯은 오프셋 4 에서 시작하고, 페이로드 안은 struct 와 같은 규칙으로
배치한다. 태그는 선언 순서대로 0 부터다. enum 의 정렬은 4 다.

**struct 필드와 enum 페이로드는 집합체도 대여도 될 수 없다.** 스칼라·슬라이스·생
포인터만 담긴다. 그래서 복사 코드 생성이 완전히 사라지고 — 모든 저장이 스칼라 하나다
— 재귀적 타입이 문법으로 불가능해져 크기 계산에 순환 검사가 필요 없다. 집합체를
품으려면 `*T` 로 가리키거나 `[]T` 에 담는다.

`const` 의 타입은 `i32` `u32` `bool` 뿐이다. 상수식은 리터럴·다른 상수·`as`·단항·이항
연산이며 컴파일 때 접힌다. 상수끼리는 순서에 상관없이 참조할 수 있고, 자기를 도로
참조하면 오류다. 상수식의 0 나눗셈은 트랩이 아니라 컴파일 오류다.

## 5. 식

우선순위, 높은 것부터:

| | |
|---|---|
| `f(..)` `a[i]` `s.f` `p.^` | 호출·인덱스·필드·역참조 |
| `-x` `!x` `&x` `&mut x` | 단항 |
| `as` | |
| `* / %` | |
| `+ -` | |
| `<< >>` | `u32` 는 논리, `i32` 는 산술 |
| `& ^ \|` | 이 순서로 |
| `== != < > <= >=` | **연쇄 금지.** `a < b < c` 는 오류 |
| `&&` | 단축 평가 |
| `\|\|` | 단축 평가 |

`a[i]` 는 **경계 검사**한다. 벗어나면 트랩. `i` 의 타입은 `u32` 다 — 음수 첨자가
문법으로 불가능해진다.

**시프트의 오른쪽도 `u32`** 다. 개수는 부호가 없다. 시프트 양은 32 로 나눈 나머지만
쓴다 — wasm 이 그렇게 한다. 나머지 이항 연산자는 양쪽 타입이 같아야 한다.

`p.^` 는 `&T` `&mut T` `*T` 전부에 쓴다. `*T` 일 때만 `unsafe` 가 필요하다.

구조체 리터럴 `Name{ a: 1, b: 2 }`, enum 리터럴 `Name.Variant` / `Name.Variant(x)`.
필드는 **전부, 선언 순서대로** 적는다. 집합체 리터럴은 `let` 초기화식과 대입 우변의
최상위에서만 쓸 수 있다. 거기서 대상 장소에 **직접 써진다** — 임시도 복사도 없다.
다른 자리에 적으면 오류다.

문법에서는 `if`/`for`/`match` 헤더의 최상위에 온 `Name{` 를 블록의 시작으로 읽는다.
괄호·대괄호·인자 목록 안에서는 그 제한이 풀린다 — 블록이 뒤따를 수 없어 모호하지
않기 때문이다.

## 6. 문

```
let x: T = e;           // 불변
let mut x: T = e;       // 가변
let x = e;              // 타입 표기는 생략할 수 있다. 초기화식의 타입이 된다
x = e;                  // 대입. 가변 장소에만
x += e;                 // += -= *= /= %= &= |= ^= <<= >>=
f(x);                   // 호출은 문이 된다. 문이 되는 식은 호출뿐이다

if e { } else if e { } else { }

for { }                       // 무한
for e { }                     // 조건
for let mut i = 0; e; s { }   // 초기화·조건·후처리

break;  continue;  return;  return e;

match e {
    A       => { }
    B(x)    => { }
    C(x, y) => { }
    _       => { }
}

unsafe { }
```

- `for` 하나뿐이다. `while` 도 `goto` 도 없다. `break`/`continue` 는 가장 안쪽 루프에만
  적용된다 (레이블 없음)
- `if`/`for` 의 조건은 `bool` 만
- **`match` 는 문이다.** 값을 만들지 않는다. 팔은 블록이다
- **패턴은 한 겹이다.** `C(Int(x), y)` 같은 중첩은 오류. 바인딩은 식별자만
- `match` 는 **완전해야 한다** — 모든 배리언트를 다루거나 `_` 가 있어야 한다. `_` 는
  마지막 팔이어야 하고, 같은 배리언트를 두 번 다루면 오류다. 대상은 enum **장소**여야
  한다 (`match n.^ { }` 처럼). 바인딩은 페이로드의 복사본이고 불변이다
- `unsafe` 는 `*T` 역참조만 허용한다. 그 외에 푸는 것이 없다
- **가변인 장소**는 이렇게 정한다: 지역변수는 `mut` 로 선언된 것, `s.f` 는 `s` 가 가변인
  것, `a[i]` 는 `a` 가 `[]mut T` 인 것, `p.^` 는 `p` 가 `&mut T` 나 `*T` 인 것.
  **매개변수는 `mut` 이 붙을 자리가 없으므로 언제나 불변이다** — 고치려면 지역변수로
  받는다. `[]mut T` 매개변수를 통해 원소를 고치는 것은 되고, 그 매개변수 자체를
  `&mut` 로 빌리는 것은 안 된다
- 반환 타입이 있는 함수는 **모든 경로에서 반환해야 한다.** `return`, 양쪽이 다 끊는
  `if`/`else`, `break` 없는 무한 `for`, 모든 팔이 끊는 완전한 `match` 가 흐름을 끊는다

**중첩 한계는 64 다.** 컴파일러가 재귀 하강이고 섀도 스택이 고정 크기라 한계가
있어야 한다. 세는 것이 둘이고 둘 다 64 다.

| | |
|---|---|
| 식 트리의 깊이 | 잎이 1. 합성 노드는 `1 + max(자식)`. `1+1+1+...` 은 파서에는 반복이지만 트리로는 깊다 |
| 문법 중첩의 깊이 | 식 하나를 읽을 때마다 하나. 괄호·단항 연산자·인자·첨자가 각각 한 겹이다. 타입과 블록과 `else if` 사슬도 함께 센다 |

세는 법도 정해 둔다. 계수기는 0 에서 시작하고, 들어갈 때 **64 이상이면 오류**,
아니면 하나 올리고 나올 때 내린다. 그래서 실제로 허용되는 것은 64 겹이다.

`expression nests too deeply`, `type nests too deeply`, `block nests too deeply`.

## 7. 대여 — 규칙 하나

`&T` 는 읽기 전용, `&mut T` 는 독점이다. 그리고:

> **`&x` / `&mut x` 는 호출의 인자 자리에서만 쓸 수 있다.**

지역변수에 묶을 수 없고(`let r = &mut x;` 는 오류), 반환할 수 없고, struct 에 담을
수 없다. 따라서 **대여는 그 호출이 끝나면 반드시 죽는다.**

그래서 별칭 검사가 이것뿐이다:

> **한 호출의 인자 목록 안에서 어떤 지역변수를 `&mut` 로 빌렸는데, 그 지역변수가
> 그 목록 안에 또 나오면 오류.**

"또 나온다"는 형태를 가리지 않는다 — 빌리든, 값으로 읽든, 다른 식 속에 있든 같다.
빌림의 뿌리 지역변수는 `.f`/`[i]`/`.^` 를 타고 내려간 밑바닥이다.

```cool
f(&mut x, &mut x)    // 오류
f(&x, &mut x)        // 오류
f(&mut x, x)         // 오류
f(&mut a[i], a[j])   // 오류 -- 뿌리가 둘 다 a
f(&x, &x)            // 된다
g(p, p)              // 된다 -- p 가 &mut T 매개변수여도. 새 대여가 아니다
```

매개변수가 대여 타입인 것은 되고, 그것을 다른 함수에 그대로 넘기는 것도 된다 —
새 대여를 만드는 것이 아니기 때문이다.

수명 분석도, 흐름 병합도, 스코프 추적도 없다. 이것이 cool0 가 안전 규칙에서 가져오는
전부다.

## 8. 호스트 ABI

컴파일러는 **순수 함수**다. 파일도 인자도 환경도 없다.

메모리는 고정 **512 페이지 (32 MiB)**, 증가 없음. `memory` 로 내보낸다.

| 주소 | |
|---|---|
| `0x0000` | `out_ptr : u32` |
| `0x0004` | `out_len : u32` |
| `0x0010` | **섀도 스택.** `0x1000` 에서 아래로 자란다 (§11) |
| `0x1000` | **소스가 놓이는 곳.** 호스트가 여기에 쓴다 |
| `0x1000 + src_len` | 힙. 프로그램이 알아서 쓴다 |
| `0x0100_0000` | **문자열 리터럴.** 컴파일러가 여기에 놓는다 (§11) |
| `0x0200_0000` | 메모리 끝 |

```
compile(src_len: u32) -> i32
```

- `0` — 성공. `out_ptr`/`out_len` 이 **컴파일된 wasm 바이트**를 가리킨다
- `1` — 실패. `out_ptr`/`out_len` 이 **진단 텍스트**를 가리킨다

진단은 ASCII 이며 한 줄에 하나다: `줄:칸: 문구`. §12 를 보라.

cool0 프로그램의 함수는 **전부 이름 그대로 내보내진다.** 그래서 cool0 로 쓴
컴파일러가 이 ABI 를 그대로 만족한다.

## 9. 결정론

같은 입력에 대해 **같은 바이트**가 나와야 한다. 두 구현(`cool0.py`, `cool0c`)의
출력을 바이트 단위로 비교하는 것이 검증 방법이므로, 배치·정렬·명령 선택·섹션
순서가 전부 이 문서로 정해져야 한다.

**명세가 정하지 않은 것이 있어 패리티가 깨지면 그것은 명세의 버그다.** 참조 구현이
임시 심판이고, 결론은 이 문서로 돌아온다.

## 10. 없는 것과 그 이유

| | |
|---|---|
| 소유권, 수명, 자동 해제 | 컴파일러가 순수 함수라 아무것도 해제하지 않는다 |
| 오버플로 검사 | 랩어라운드로 정의했다. wasm 이 공짜로 하는 일이다 |
| 제네릭, 인터페이스, 클로저 | 컴파일러를 쓰는 데 필요 없다 |
| 모듈·임포트 | 한 파일이 한 프로그램이다 |
| `i64`/`u64`, 부동소수점 | 주소가 32비트고 컴파일러는 실수를 쓰지 않는다 |
| 문자열 타입 | `[]u8` 이면 된다 |
| `while`, `goto`, 레이블 | `for` 하나. wasm 이 구조적이라 goto 는 내려갈 곳이 없다 |
| 중첩 패턴, 식 형태 `match` | 검사기와 코드 생성이 커진다 |
| 표준 라이브러리 | 없다. 필요한 것은 프로그램이 자기 안에 쓴다 |

## 11. 방출 규약

§9 가 요구하는 바이트 단위 동일성은 여기까지 정해져야 나온다. **최적화는 없다.**
코드 생성은 문법 지향적이고, 짧게 줄일 수 있는 자리도 줄이지 않는다 — 균일한 것이
전사하기 쉽고, 그것이 이 계획의 전부다.

### 모듈

섹션은 wasm 이 요구하는 정규 순서로만 나온다: type, function, memory, global,
export, code, data. import·table·start·element 는 없다.

| | |
|---|---|
| type | 서명을 **첫 등장 순**으로 중복 제거. 등장 순서는 함수 선언 순서 |
| function | 함수를 **선언 순서**로. 인덱스가 곧 선언 순서다 |
| memory | `min = max = 512` 페이지 |
| global | 하나. `$sp : mut i32 = 0x1000` |
| export | 함수를 선언 순서로 전부, 그다음 `memory` |
| code | 함수 본문 |
| data | 문자열 리터럴. 활성 세그먼트 하나씩 |

문자열 리터럴은 `0x0100_0000` 부터 **첫 등장 순**으로 붙여 놓는다. 패딩은 없고,
바이트열이 같으면 주소를 공유한다. 등장 순서는 함수 선언 순서 안에서 식을 왼쪽부터
훑은 순서다.

### 값 표현

| | |
|---|---|
| `i32` `u32` `bool` `&T` `*T` | wasm 값 하나 (`i32`) |
| `[]T` | wasm 값 **둘** — `ptr`, `len` 순 |
| struct, enum | 값이 아니다. 메모리에만 산다 |
| `bool` | `0` 또는 `1` |

지역변수는 wasm 지역변수에 놓는다. 다만 **집합체이거나 주소를 취한 것**(`&x` 나
`&mut x` 의 뿌리가 된 것)은 섀도 프레임에 놓는다. 주소를 취한 매개변수는 wasm
매개변수로 받은 뒤 프롤로그에서 프레임으로 복사한다.

wasm 지역변수 인덱스는 매개변수부터 선언 순서, 그다음 본문 지역변수가 선언 순서,
그다음 컴파일러가 쓰는 임시 변수다. 전부 `i32` 라 지역변수 선언은 한 덩어리다.

### 섀도 프레임

프레임 안의 자리는 **선언 순서대로**, 각자 자기 정렬로 잡고, 프레임 크기는 4 의
배수로 올린다. 프레임이 비면 프롤로그도 에필로그도 없다.

```
프롤로그   global.get $sp; i32.const N; i32.sub; global.set $sp
에필로그   global.get $sp; i32.const N; i32.add; global.set $sp
```

에필로그는 모든 `return` 앞과 본문 끝에 나온다. 장소의 주소는 `global.get $sp` 에
오프셋을 더해 만든다 — 프레임 포인터 지역변수를 따로 두지 않는다. 호출된 함수가
`$sp` 를 복원하므로 본문 내내 `$sp` 는 그대로다.

넘침 검사는 없다. 넘치면 `0x0010` 아래로 내려가 결국 트랩이다.

### 주소 계산

**메모리 접근의 `offset` 즉치값은 언제나 0 이다.** 오프셋은 `i32.const` + `i32.add`
로 명시한다. 오프셋이 0 이어도 그대로 낸다. 정렬 즉치값은 자연 정렬이다 — 4바이트는
2, 1바이트는 0.

| | |
|---|---|
| `i32` `u32` `&T` `*T` | `i32.load` / `i32.store` |
| `bool` `u8` | `i32.load8_u` / `i32.store8` |

`u8` 은 읽으면 제로 확장으로 `u32` 가 되고, 쓸 때는 `i32.store8` 이 잘라낸다.

**슬라이스는 메모리에서도 두 조각이다.** 필드나 페이로드에 들어 있는 `[]T` 를 읽고
쓰는 것은 `off` 와 `off + 4` 에 대한 접근 두 번이며, `ptr` 이 먼저다. 집합체 리터럴이
슬라이스 필드를 채울 때도 마찬가지다 — 값 하나가 아니다.

### 명령 선택

- `-x` → `i32.const 0` 다음 `x`, `i32.sub`
- `!x` → `i32.eqz`
- `as` → 명령 없음
- `/` `%` `>>` 와 비교는 피연산자 타입으로 부호를 정한다. `i32` 는 부호 있는 것,
  `u32` 와 `*T` 는 없는 것
- `&&` `||` → `if (result i32)`. 짧은 쪽에 상수를 놓는다
- `a[i]` → 슬라이스를 임시 둘에, 첨자를 임시 하나에 넣고
  `i >= len` 이면 `unreachable`, 아니면 `ptr + i * 크기`. 원소 크기가 1 이어도
  `i32.const 1; i32.mul` 을 낸다

### 제어 흐름

```
if       <조건> if ... [else ...] end          else 는 있을 때만 낸다
for      <초기화>
         block                                  ; break 목적지
           loop
             <조건> i32.eqz br_if 1             ; 조건이 있을 때만
             block                              ; continue 목적지
               <몸통>
             end
             <후처리>
             br 0
           end
         end
match    <대상 주소> -> 임시
         block
           팔마다: 태그를 읽어 비교, if <바인딩><몸통> br 1 end
           `_` 팔의 몸통, 없으면 unreachable
         end
```

`continue` 블록은 후처리가 없어도 낸다. `match` 의 팔은 선언 순서가 아니라 **적힌
순서**로 비교한다. 완전성이 보장되므로 마지막 `unreachable` 은 죽은 코드다.

반환 타입이 있는 함수는 본문 끝에 `unreachable` 을 붙인다 — 모든 경로가 반환한다는
것은 이미 검사했고, wasm 검증기는 그 분석을 하지 않기 때문이다.

## 12. 진단

**첫 오류에서 멈춘다.** 출력은 한 줄이고 `\n` 으로 끝난다.

```
줄:칸: 문구
```

줄과 칸은 1 부터 센다. 칸은 바이트 수이며 탭도 하나로 센다. 위치는 오류가 붙는 식이나
문의 첫 토큰이다. 문구는 ASCII 소문자로 시작하는 영어 한 줄이며, 이름은 백틱으로
감싼다. 문구 하나하나가 명세의 일부다 — 두 구현이 같은 바이트를 내야 하기 때문이다.

참조 구현의 오류 목록이 그 사전이고, 패리티 테스트가 그것을 강제한다.
