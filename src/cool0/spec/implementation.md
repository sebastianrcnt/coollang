# cool0 구현 명세

[`language.md`](language.md) 가 정한 뜻을 **공식 cool0 컴파일러가 wasm 으로 정확히
어떻게 옮기는가**를 정한다.

§8 이 요구하는 바이트 단위 동일성은 여기까지 정해져야 나온다. 두 구현
(`cool0.py`, `cool0c`)의 출력을 바이트로 비교하는 것이 이 프로젝트의 검증
방법이므로, 배치·정렬·명령 선택·섹션 순서·진단 문구가 **전부 이 문서로** 정해져야
한다.

**최적화는 없다.** 코드 생성은 문법 지향적이고, 짧게 줄일 수 있는 자리도 줄이지
않는다 — 균일한 것이 손으로 옮겨 적기 쉽고, 그것이 부트스트랩 계획의 전부다.

---

## 1. 타깃

| | |
|---|---|
| 명령 집합 | **WebAssembly 1.0 (MVP)** 하나 |
| 주소 | wasm32. 포인터는 `i32` |
| 임포트 | 없음 |
| WASI | 없음 |
| I/O | 없음 |
| 확장 | 없음 (multi-value, bulk memory, sign-extension 전부 쓰지 않는다) |

wasm 을 고른 이유는 이식성만이 아니다. **구조적 제어 흐름**(`block`/`loop`/`if`/
`end`)이 재귀 하강 파서의 재귀 구조와 정확히 일치해서 점프 대상 백패치가 통째로
사라진다. 그리고 오브젝트 포맷도, 링커도, 호출 규약도, 레지스터 할당도 없다.

## 2. 데이터 표현

### 값

| | |
|---|---|
| `i32` `u32` `bool` `&T` `*T` | wasm 값 하나 (`i32`) |
| `[]T` | wasm 값 **둘** — `ptr`, `len` 순 |
| struct, enum | 값이 아니다. 메모리에만 산다 |
| `bool` | `0` 또는 `1` |

### 메모리

| | 크기 | 정렬 |
|---|---|---|
| `i32` `u32` | 4 | 4 |
| `bool` | 1 | 1. 값은 `0` 또는 `1` |
| `u8` | 1 | 1 |
| `[]T` `[]mut T` | 8 | 4. `(ptr, len)` 순서 |
| `&T` `&mut T` `*T` | 4 | 4 |

**슬라이스는 메모리에서도 두 조각이다.** 필드나 페이로드에 들어 있는 `[]T` 를 읽고
쓰는 것은 `off` 와 `off + 4` 에 대한 접근 두 번이며, `ptr` 이 먼저다. 집합체 리터럴이
슬라이스 필드를 채울 때도 마찬가지다 — 값 하나가 아니다.

### struct 배치

필드는 **선언 순서대로**, 각자 자기 정렬로 놓는다. struct 의 정렬은 필드 정렬의
최대값이고, 크기는 그 배수로 올린다. 빈 struct 는 크기 0, 정렬 1 이다.

### enum 배치

`태그(u32) + 페이로드 슬롯` 이다. 슬롯 크기는 배리언트 페이로드 크기의 최대값이다.
페이로드 슬롯은 **오프셋 4** 에서 시작하고, 페이로드 안은 struct 와 같은 규칙으로
배치한다. 태그는 선언 순서대로 **0 부터**다. enum 의 정렬은 언제나 4 이고, 크기는
`align_up(4 + 슬롯, 4)` 다.

## 3. 호출 규약

| | |
|---|---|
| 스칼라 매개변수 | wasm 매개변수 하나 |
| 슬라이스 매개변수 | wasm 매개변수 **둘** 로 펼친다 (`ptr`, `len`) |
| 대여 매개변수 | 주소 하나 (`i32`) |
| 집합체 매개변수 | **금지** — 값으로 넘길 수 없다 |
| 반환 | 값 하나 또는 없음. wasm 1.0 이 결과를 하나만 주기 때문이다 |
| 집합체 반환 | **금지** |
| 슬라이스 반환 | **금지** — 값이 둘이라 결과 하나에 담기지 않는다 |
| 대여 반환 | **금지** (language.md §7) |

인자는 왼쪽에서 오른쪽으로 평가해 쌓는다. `&x` 는 주소를 낸다.

## 4. 모듈 배치

섹션은 wasm 이 요구하는 정규 순서로만 나온다: type, function, memory, global,
export, code, data. **import·table·start·element·custom 은 없다.**

| | |
|---|---|
| type | 서명을 **첫 등장 순**으로 중복 제거. 등장 순서는 함수 선언 순서 |
| function | 함수를 **선언 순서**로. 인덱스가 곧 선언 순서다 |
| memory | `min = max = 512` 페이지 |
| global | 하나. `$sp : mut i32 = 0x1000` |
| export | 함수를 선언 순서로 전부, 그다음 `memory` |
| code | 함수 본문 |
| data | 문자열 리터럴. 활성 세그먼트 하나씩 |

함수가 하나도 없으면 type·function·code 섹션이 없고, 문자열이 없으면 data 섹션이
없다.

**지역변수 인덱스**는 매개변수부터 선언 순서, 그다음 본문 지역변수가 선언 순서,
그다음 컴파일러가 쓰는 임시 변수다. 전부 `i32` 라 지역변수 선언은 한 덩어리다.

지역변수는 wasm 지역변수에 놓는다. 다만 **집합체이거나 주소를 취한 것**(`&x` 나
`&mut x` 의 뿌리가 된 것)은 섀도 프레임에 놓는다. 주소를 취한 매개변수는 wasm
매개변수로 받은 뒤 프롤로그에서 프레임으로 복사한다.

**문자열 리터럴**은 `0x0100_0000` 부터 **첫 등장 순**으로 붙여 놓는다. 패딩은 없고,
바이트열이 같으면 주소를 공유한다. 등장 순서는 함수 선언 순서 안에서 식을 왼쪽부터
훑은 순서다.

## 5. 코드 생성

### 주소 계산

**메모리 접근의 `offset` 즉치값은 언제나 0 이다.** 오프셋은 `i32.const` + `i32.add`
로 명시한다. 오프셋이 0 이어도 그대로 낸다. 정렬 즉치값은 자연 정렬이다 — 4바이트는
2, 1바이트는 0.

| | |
|---|---|
| `i32` `u32` `&T` `*T` | `i32.load` / `i32.store` |
| `bool` `u8` | `i32.load8_u` / `i32.store8` |

`u8` 은 읽으면 제로 확장으로 `u32` 가 되고, 쓸 때는 `i32.store8` 이 잘라낸다.

### 연산자

- `-x` → `i32.const 0` 다음 `x`, `i32.sub`
- `!x` → `i32.eqz`
- `as` → **명령 없음** (비트 재해석)
- `p: *T + i: u32` → `p`, `i`, `i32.const sizeof(T)`, `i32.mul`, `i32.add`
- `/` `%` `>>` 와 비교는 피연산자 타입으로 부호를 정한다. `i32` 는 부호 있는 것,
  `u32` 와 `*T` 는 없는 것
- `&&` `||` → `if (result i32)`. 짧은 쪽에 상수를 놓는다

### 인덱싱

`a[i]` → 슬라이스를 임시 둘에, 첨자를 임시 하나에 넣고 `i >= len` 이면 `unreachable`,
아니면 `ptr + i * 크기`. **원소 크기가 1 이어도 `i32.const 1; i32.mul` 을 낸다.**

### 슬라이스 구성과 투영

`slice(p, len)`과 `slice_mut(p, len)`은 두 피연산자를 `(ptr, len)` 순서로 그대로
방출하며 식 자체의 명령은 없다. `s.ptr`과 `s.len`은 각각 그 두 슬롯을 투영한다.
가변성 약화(`&mut T`→`&T`, `[]mut T`→`[]T`)도 검사기에서 권한만 버리므로 명령을
만들지 않는다.

### 제어 흐름

```
if       <조건> if ... [else ...] end          else 는 있을 때만 낸다
for      <초기화>
         block                                  ; break 목적지
           loop
             <조건> i32.eqz br_if 1             ; 조건이 있을 때만
             block                              ; continue 목적지
               <몸통>
             end
             <후처리>
             br 0
           end
         end
match    <대상 주소> -> 임시
         block
           팔마다: 태그를 읽어 비교, if <바인딩><몸통> br 1 end
           `_` 팔의 몸통, 없으면 unreachable
         end
```

`continue` 블록은 후처리가 없어도 낸다. `match` 의 팔은 선언 순서가 아니라 **적힌
순서**로 비교한다. 완전성이 보장되므로 마지막 `unreachable` 은 죽은 코드다.

### return 과 함수의 꼬리

에필로그(§6)는 모든 `return` 앞과 본문 끝에 나온다.

반환 타입이 있는 함수는 본문 끝에 `unreachable` 을 붙인다 — 모든 경로가 반환한다는
것은 이미 검사했고(language.md §9), wasm 검증기는 그 분석을 하지 않기 때문이다.

### unsafe 역참조

`unsafe` 는 코드를 만들지 않는다. `p.^` 는 검사 없이 `p` 값을 주소로 써서 load/store
한다. 범위 밖이면 wasm 이 트랩한다.

## 6. 컴파일러 런타임

### 섀도 프레임

프레임 안의 자리는 **선언 순서대로**, 각자 자기 정렬로 잡고, 프레임 크기는 4 의
배수로 올린다. 프레임이 비면 프롤로그도 에필로그도 없다.

```
프롤로그   global.get $sp; i32.const N; i32.sub; global.set $sp
           global.get $sp; i32.const SHADOW_FLOOR; i32.lt_u
           if (void) unreachable end
에필로그   global.get $sp; i32.const N; i32.add; global.set $sp
```

장소의 주소는 `global.get $sp` 에 오프셋을 더해 만든다 — 프레임 포인터 지역변수를
따로 두지 않는다. 호출된 함수가 `$sp` 를 복원하므로 본문 내내 `$sp` 는 그대로다.

**넘침 검사는 프롤로그에 있다.** 프레임을 쓰는 함수(`frame_size != 0`)만 해당하고,
검사는 `global.set $sp` 직후 -- 주소를 취한 매개변수를 프레임으로 복사하는 코드보다
**앞에** 나온다. 영역은 `SHADOW_FLOOR`(`0x0180_0000`)–`SHADOW_TOP`(`0x0200_0000`),
즉 **8 MiB** 다. `$sp` 가 `SHADOW_FLOOR` 아래로 내려가면 `unreachable` 로 곧장
트랩한다 -- 예약 슬롯이나 `out_ptr`/`out_len` 을 건드릴 자리에 닿기 전이다.

이전 배치(`0x0010`–`0x1000`, 4080 바이트)에서는 검사가 없어, 넘치면 `$sp` 가
`0x0000` 을 지나 호스트 ABI 슬롯(`out_ptr`/`out_len`)을 조용히 덮은 뒤에야, 그것도
한참 더 내려가 주소가 음수가 되어야 트랩했다. "넘치면 트랩"이 아니라 **트랩 전에
호스트 ABI 를 먼저 잃는** 결함이었다.

검사를 그 자리에 그대로 붙였다면 여전히 속았을 것이다: `i32.lt_u` 는 부호 없는
비교라, 언더플로한 `$sp`(거대한 양수로 랩어라운드한 값)가 `0x1000` 보다 작다는
조건을 통과하지 못해 그냥 넘어간다. 그래서 스택을 메모리 위쪽으로 옮겼다 --
`SHADOW_FLOOR` 위에서 언더플로가 나면 `$sp` 는 `0xFFFF_FFxx` 근방으로 랩어라운드
하는데, 이는 `SHADOW_FLOOR` 보다 여전히 크므로 `i32.lt_u` 검사가 속지 않는다.

프레임을 쓰는 함수의 재귀 깊이는 이제 이 검사가 지킨다. cool0 컴파일러 자신은
집합체도 대여도 쓰지 않아 프레임이 하나도 없으므로 프롤로그가 붙는 함수가 없다.

### 범프 할당

컴파일러는 **아무것도 해제하지 않는다.** 한 번 돌고 호스트가 메모리를 회수한다.
힙은 소스 뒤에서 시작해 위로 자라는 포인터 하나이며, 그 관리는 프로그램의 몫이다
(§7 의 메모리 지도).

### 문자열 리터럴 영역

`0x0100_0000` 부터. §4 를 보라.

## 7. 부트스트랩 호스트 ABI

컴파일러는 **순수 함수**다. 파일도 인자도 환경도 없다.

메모리는 고정 **512 페이지 (32 MiB)**, 증가 없음. `memory` 로 내보낸다.

| 주소 | |
|---|---|
| `0x0000` | `out_ptr : u32` |
| `0x0004` | `out_len : u32` |
| `0x1000` | **소스가 놓이는 곳.** 호스트가 여기에 쓴다 |
| `0x1000 + src_len` | 힙. 프로그램이 알아서 쓴다 |
| `0x0100_0000` | **문자열 리터럴.** 컴파일러가 여기에 놓는다 (§4) |
| `0x0180_0000` | **섀도 스택 하한 (`SHADOW_FLOOR`).** 넘으면 트랩한다 (§6) |
| `0x0200_0000` | **섀도 스택 초기값 (`$sp`).** 아래로 자란다 (§6). 메모리 끝이기도 하다 |

```
compile(src_len: u32) -> i32
```

- `0` — 성공. `out_ptr`/`out_len` 이 **컴파일된 wasm 바이트**를 가리킨다
- `1` — 실패. `out_ptr`/`out_len` 이 **진단 텍스트**를 가리킨다

cool0 프로그램의 함수는 **전부 이름 그대로 내보내진다.** 그래서 cool0 로 쓴
컴파일러가 이 ABI 를 그대로 만족한다.

## 8. 결정론

같은 입력에 대해 **같은 바이트**가 나와야 한다.

| 정해져야 하는 것 | 어디 |
|---|---|
| 명령 선택 | §5 |
| 선언 순서 | §4 — 함수 인덱스, export 순서, 타입 중복 제거 순서 |
| 리터럴 순서 | §4 — 문자열의 첫 등장 순, 주소 공유 |
| 배치와 정렬 | §2 |
| 지역변수·임시 변수 인덱스 | §4 |
| 진단 문구 | §9 |

**명세가 정하지 않은 것이 있어 패리티가 깨지면 그것은 명세의 버그다.** 참조 구현이
임시 심판이고, 결론은 이 문서로 돌아온다.

## 9. 진단

**첫 오류에서 멈춘다.** 출력은 한 줄이고 `\n` 으로 끝난다.

```
줄:칸: 문구
```

줄과 칸은 1 부터 센다. 칸은 바이트 수이며 탭도 하나로 센다. 위치는 오류가 붙는 식이나
문의 첫 토큰이다. 문구는 ASCII 소문자로 시작하는 영어 한 줄이며, 이름은 백틱으로
감싼다. 문구 하나하나가 명세의 일부다 — 두 구현이 같은 바이트를 내야 하기 때문이다.

참조 구현의 오류 목록이 그 사전이고, 패리티 테스트가 그것을 강제한다.
