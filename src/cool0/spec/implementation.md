# cool0 구현 명세

[`language.md`](language.md) 가 정한 뜻을 **공식 cool0 컴파일러가 wasm 으로 정확히
어떻게 옮기는가**를 정한다.

§8 이 요구하는 바이트 단위 동일성은 여기까지 정해져야 나온다. 두 구현
(`cool0.py`, `cool0c`)의 출력을 바이트로 비교하는 것이 이 프로젝트의 검증
방법이므로, 배치·정렬·명령 선택·섹션 순서·진단 문구가 **전부 이 문서로** 정해져야
한다.

**최적화는 없다.** 코드 생성은 문법 지향적이고, 짧게 줄일 수 있는 자리도 줄이지
않는다 — 균일한 것이 손으로 옮겨 적기 쉽고, 그것이 부트스트랩 계획의 전부다.

---

## 1. 타깃

| | |
|---|---|
| 명령 집합 | **WebAssembly 1.0 (MVP)** 하나 |
| 주소 | wasm32. 포인터는 `i32` |
| 임포트 | 없음 |
| WASI | 없음 |
| I/O | 없음 |
| 확장 | 없음 (multi-value, bulk memory, sign-extension 전부 쓰지 않는다) |

wasm 을 고른 이유는 이식성만이 아니다. **구조적 제어 흐름**(`block`/`loop`/`if`/
`end`)이 재귀 하강 파서의 재귀 구조와 정확히 일치해서 점프 대상 백패치가 통째로
사라진다. 그리고 오브젝트 포맷도, 링커도, 호출 규약도, 레지스터 할당도 없다.

## 2. 데이터 표현

### 값

| | |
|---|---|
| `i32` `u32` `bool` `&T` `*T` | wasm 값 하나 (`i32`) |
| `[]T` | wasm 값 **둘** — `ptr`, `len` 순 |
| struct, enum | 값이 아니다. 메모리에만 산다 |
| `bool` | `0` 또는 `1` |

### 메모리

| | 크기 | 정렬 |
|---|---|---|
| `i32` `u32` | 4 | 4 |
| `bool` | 1 | 1. 값은 `0` 또는 `1` |
| `u8` | 1 | 1 |
| `[]T` `[]mut T` | 8 | 4. `(ptr, len)` 순서 |
| `&T` `&mut T` `*T` | 4 | 4 |

**슬라이스는 메모리에서도 두 조각이다.** 필드나 페이로드에 들어 있는 `[]T` 를 읽고
쓰는 것은 `off` 와 `off + 4` 에 대한 접근 두 번이며, `ptr` 이 먼저다. 집합체 리터럴이
슬라이스 필드를 채울 때도 마찬가지다 — 값 하나가 아니다.

### struct 배치

필드는 **선언 순서대로**, 각자 자기 정렬로 놓는다. struct 의 정렬은 필드 정렬의
최대값이고, 크기는 그 배수로 올린다. 빈 struct 는 크기 0, 정렬 1 이다.

### enum 배치

`태그(u32) + 페이로드 슬롯` 이다. 슬롯 크기는 배리언트 페이로드 크기의 최대값이다.
페이로드 슬롯은 **오프셋 4** 에서 시작하고, 페이로드 안은 struct 와 같은 규칙으로
배치한다. 태그는 선언 순서대로 **0 부터**다. enum 의 정렬은 언제나 4 이고, 크기는
`align_up(4 + 슬롯, 4)` 다.

## 3. 호출 규약

| | |
|---|---|
| 스칼라 매개변수 | wasm 매개변수 하나 |
| 슬라이스 매개변수 | wasm 매개변수 **둘** 로 펼친다 (`ptr`, `len`) |
| 대여 매개변수 | 주소 하나 (`i32`) |
| 집합체 매개변수 | **금지** — 값으로 넘길 수 없다 |
| 반환 | 값 하나 또는 없음. wasm 1.0 이 결과를 하나만 주기 때문이다 |
| 집합체 반환 | **금지** |
| 슬라이스 반환 | **금지** — 값이 둘이라 결과 하나에 담기지 않는다 |
| 대여 반환 | **금지** (language.md §7) |

인자는 왼쪽에서 오른쪽으로 평가해 쌓는다. `&x` 는 주소를 낸다.

## 4. 모듈 배치

섹션은 wasm 이 요구하는 정규 순서로만 나온다: type, function, memory, global,
export, code, data. **import·table·start·element·custom 은 없다.**

| | |
|---|---|
| type | 서명을 **첫 등장 순**으로 중복 제거. 등장 순서는 함수 선언 순서 |
| function | 함수를 **선언 순서**로. 인덱스가 곧 선언 순서다 |
| memory | `min = max = 8192` 페이지 (512 MiB) |
| global | 하나. `$sp : mut i32 = SHADOW_TOP` (§6) |
| export | 함수를 선언 순서로 전부, 그다음 `memory` |
| code | 함수 본문 |
| data | 문자열 리터럴. 활성 세그먼트 하나씩 |

함수가 하나도 없으면 type·function·code 섹션이 없고, 문자열이 없으면 data 섹션이
없다.

**지역변수 인덱스**는 매개변수부터 선언 순서, 그다음 본문 지역변수가 선언 순서,
그다음 컴파일러가 쓰는 임시 변수다. 전부 `i32` 라 지역변수 선언은 한 덩어리다.

지역변수는 wasm 지역변수에 놓는다. 다만 **집합체이거나 주소를 취한 것**(`&x` 나
`&mut x` 의 뿌리가 된 것)은 섀도 프레임에 놓는다. 주소를 취한 매개변수는 wasm
매개변수로 받은 뒤 프롤로그에서 프레임으로 복사한다.

**문자열 리터럴**은 `0x1000_0000` 부터 **첫 등장 순**으로 붙여 놓는다. 패딩은 없고,
바이트열이 같으면 주소를 공유한다. 등장 순서는 함수 선언 순서 안에서 식을 왼쪽부터
훑은 순서다.

## 5. 코드 생성

### 주소 계산

**메모리 접근의 `offset` 즉치값은 언제나 0 이다.** 오프셋은 `i32.const` + `i32.add`
로 명시한다. 오프셋이 0 이어도 그대로 낸다. 정렬 즉치값은 자연 정렬이다 — 4바이트는
2, 1바이트는 0.

| | |
|---|---|
| `i32` `u32` `&T` `*T` | `i32.load` / `i32.store` |
| `bool` `u8` | `i32.load8_u` / `i32.store8` |

`u8` 은 읽으면 제로 확장으로 `u32` 가 되고, 쓸 때는 `i32.store8` 이 잘라낸다.

### 연산자

- `-x` → `i32.const 0` 다음 `x`, `i32.sub`
- `!x` → `i32.eqz`
- `as` → **명령 없음** (비트 재해석)
- `/` `%` `>>` 와 비교는 피연산자 타입으로 부호를 정한다. `i32` 는 부호 있는 것,
  `u32` 와 `*T` 는 없는 것
- `&&` `||` → `if (result i32)`. 짧은 쪽에 상수를 놓는다

### 인덱싱

`a[i]` → 슬라이스를 임시 둘에, 첨자를 임시 하나에 넣고 `i >= len` 이면 `unreachable`,
아니면 `ptr + i * 크기`. **원소 크기가 1 이어도 `i32.const 1; i32.mul` 을 낸다.**

### 슬라이스 구성과 투영

`slice(p, len)`과 `slice_mut(p, len)`은 두 피연산자를 `(ptr, len)` 순서로 그대로
방출하며 식 자체의 명령은 없다. `offset(p, i)`는 `p`, `i`, `i32.const sizeof(T)`,
`i32.mul`, `i32.add` 다 -- 원소 크기가 1이어도 `i32.mul`을 낸다 (`a[i]`와 같다). `s.ptr`과 `s.len`은 각각 그 두 슬롯을 투영한다.
가변성 약화(`&mut T`→`&T`, `[]mut T`→`[]T`)도 검사기에서 권한만 버리므로 명령을
만들지 않는다.

### 제어 흐름

```
if       <조건> if ... [else ...] end          else 는 있을 때만 낸다
for      <초기화>
         block                                  ; break 목적지
           loop
             <조건> i32.eqz br_if 1             ; 조건이 있을 때만
             block                              ; continue 목적지
               <몸통>
             end
             <후처리>
             br 0
           end
         end
match    <대상 주소> -> 임시                          ; 문 형태: block (void)
         block                                        ; 식 형태: block (result i32)
           팔마다: 태그를 읽어 비교, if <바인딩><몸통> br 1 end
           `_` 팔의 몸통, 없으면 unreachable
         end
```

`continue` 블록은 후처리가 없어도 낸다. `match` 의 팔은 선언 순서가 아니라 **적힌
순서**로 비교한다. 완전성이 보장되므로 마지막 `unreachable` 은 죽은 코드다.

**식 형태 match** (language.md §5) 는 같은 모양이되, 바깥 `block` 이 `(result
i32)` 이고 각 팔의 `<몸통>` 이 문 목록이 아니라 식 하나를 계산해 스택에 남긴다.
팔을 감싸는 `if` 는 여전히 `(void)` 다 -- 안에서 값을 얹고 곧장 `br 1` 로 바깥
`block` 까지 넘기므로 `if` 자신은 값을 내지 않아도 된다. cool0 의 스칼라 타입은
전부 wasm 값 하나(`i32`)이므로 결과 타입은 언제나 `i32` 다 (§2) -- 슬라이스와
집합체는 애초에 식 형태의 결과가 될 수 없다(language.md §5, §9).

### return 과 함수의 꼬리

에필로그(§6)는 모든 `return` 앞과 본문 끝에 나온다.

반환 타입이 있는 함수는 본문 끝에 `unreachable` 을 붙인다 — 모든 경로가 반환한다는
것은 이미 검사했고(language.md §9), wasm 검증기는 그 분석을 하지 않기 때문이다.

### unsafe 역참조

`unsafe` 는 코드를 만들지 않는다. `p.^` 는 검사 없이 `p` 값을 주소로 써서 load/store
한다. 범위 밖이면 wasm 이 트랩한다.

## 6. 컴파일러 런타임

### 섀도 프레임

프레임 안의 자리는 **선언 순서대로**, 각자 자기 정렬로 잡고, 프레임 크기는 4 의
배수로 올린다. 프레임이 비면 프롤로그도 에필로그도 없다.

```
프롤로그   global.get $sp; i32.const N; i32.sub; global.set $sp
           global.get $sp; i32.const SHADOW_FLOOR; i32.lt_u
           if (void) unreachable end
에필로그   global.get $sp; i32.const N; i32.add; global.set $sp
```

장소의 주소는 `global.get $sp` 에 오프셋을 더해 만든다 — 프레임 포인터 지역변수를
따로 두지 않는다. 호출된 함수가 `$sp` 를 복원하므로 본문 내내 `$sp` 는 그대로다.

**넘침 검사는 프롤로그에 있다.** 프레임을 쓰는 함수(`frame_size != 0`)만 해당하고,
검사는 `global.set $sp` 직후 -- 주소를 취한 매개변수를 프레임으로 복사하는 코드보다
**앞에** 나온다. 영역은 `SHADOW_FLOOR`(`0x1800_0000`)–`SHADOW_TOP`(`0x2000_0000`),
즉 **128 MiB** 다. `$sp` 가 `SHADOW_FLOOR` 아래로 내려가면 `unreachable` 로 곧장
트랩한다 -- 예약 슬롯이나 `out_ptr`/`out_len` 을 건드릴 자리에 닿기 전이다.

이전 배치(`0x0010`–`0x1000`, 4080 바이트)에서는 검사가 없어, 넘치면 `$sp` 가
`0x0000` 을 지나 호스트 ABI 슬롯(`out_ptr`/`out_len`)을 조용히 덮은 뒤에야, 그것도
한참 더 내려가 주소가 음수가 되어야 트랩했다. "넘치면 트랩"이 아니라 **트랩 전에
호스트 ABI 를 먼저 잃는** 결함이었다.

검사를 그 자리에 그대로 붙였다면 여전히 속았을 것이다: `i32.lt_u` 는 부호 없는
비교라, 언더플로한 `$sp`(거대한 양수로 랩어라운드한 값)가 `0x1000` 보다 작다는
조건을 통과하지 못해 그냥 넘어간다. 그래서 스택을 메모리 위쪽으로 옮겼다 --
`SHADOW_FLOOR` 위에서 언더플로가 나면 `$sp` 는 `0xFFFF_FFxx` 근방으로 랩어라운드
하는데, 이는 `SHADOW_FLOOR` 보다 여전히 크므로 `i32.lt_u` 검사가 속지 않는다.

프레임을 쓰는 함수의 재귀 깊이는 이제 이 검사가 지킨다.

`cool0c.cool0` 자신은 함수 수백 개 중 **정확히 하나**만 프레임을 쓴다 — `compile_n`
이 `c: Ctx` 의 주소를 취하기 때문이다. 나머지는 전부 그 하나를 `&mut Ctx` /
`&Ctx` 로 넘겨받으므로 프레임이 없다. 즉 컴파일러의 재귀(파서)는 프롤로그 검사가
아니라 **명시적 깊이 한계**(`expression nests too deeply`, `block nests too
deeply`, `type nests too deeply`)가 지킨다. 이 비대칭은 의도된 것이다: 대여만
넘기면 집합체를 쓰면서도 프레임이 안 생긴다.

### 범프 할당

컴파일러는 **아무것도 해제하지 않는다.** 한 번 돌고 호스트가 메모리를 회수한다.
힙은 소스 뒤에서 시작해 위로 자라는 포인터 하나이며, 그 관리는 프로그램의 몫이다
(§7 의 메모리 지도).

예외가 하나 있고, 그것이 gh #5 C 다: **함수 본문의 노드는 그 함수를 내보내고 나면
회수된다.** 노드 아레나에는 표시(watermark)가 하나 있고, 본문마다 거기로 되돌린다.
해제가 아니라 되감기이므로 자유 목록도 수명 추적도 없다 -- 되돌리는 시점이 딱
하나(함수 하나가 끝나는 자리)뿐이라서 규칙이 "그 본문의 노드를 가리키는 것은 그
본문 밖으로 나가지 않는다" 하나로 끝난다.

그래서 순서가 이렇게 된다:

```
렉싱      선언마다: S1 토큰 작업장을 채우고 파싱 뒤 바로 되쓴다
파싱      선언마다: 머리를 아레나에 남기고,
          함수면 본문을 파싱해 **세고 나서 되감는다** (소스 위치만 남긴다)
검사      선언·서명·타입·상수까지. 본문은 아직 아니다
방출      함수마다: 본문을 다시 파싱 -> 검사 -> 방출 -> 되감는다
```

본문을 두 번 파싱한다. 첫 번째는 구문 오류를 **소스 순서대로** 내기 위해서이고
(선언 자리에서 파싱하므로 순서가 그대로다), 검사기 표를 정확히 잡을 만큼 세기
위해서다. 렉싱과 파싱은 이 컴파일러에서 가장 싼 단계라 두 번 도는 값이 싸다.

동시에 살아 있는 AST 는 **선언부 + 가장 큰 본문 하나**이고, 노드 아레나도 그만큼만
예약한다. 첫 렉싱 순회가 선언별 토큰 수와 이름 용량을 세고, 두 번째 순회가 실제로
인턴하고 파싱한다. 본문은
최상위 `fn` 뒤의 중괄호다. `cool0c.cool0` 자신으로 재면 토큰의 86% 가 본문 안에
있고, 노드 아레나가 **2,970,016 -> 511,448 바이트 (83% 감소)** 다.

방출 중에 진단이 나오면 모듈은 이미 절반쯤 쓰여 있다. `err_open` 이 `out` 을 처음
으로 되감으므로 진단 자체는 성하지만, **그 뒤로 아무것도 더 쓰면 안 된다** --
본문 하나가 실패하면 방출을 그 자리에서 멈춘다.

### 문자열 리터럴 영역

`0x1000_0000` 부터. §4 를 보라.

## 7. 부트스트랩 호스트 ABI

컴파일러는 **순수 함수**다. 파일도 인자도 환경도 없다.

메모리는 고정 **8192 페이지 (512 MiB)**, 증가 없음. `memory` 로 내보낸다.

한때 512 페이지(32 MiB)였다. 그 숫자는 임의의 선택이었고, 정작 그것이 무엇을
가두는지가 어디에도 안 적혀 있었다 -- **cool0 가 내보내는 모든 프로그램**이다.
cool1 컴파일러는 cool0 로 쓰고 `cool0c` 가 컴파일하므로, 이 숫자가 cool1 이
다룰 수 있는 크기의 진짜 상한이다 (gh #5). 배치를 통째로 16 배로 옮겼다.

| 주소 | |
|---|---|
| `0x0000` | `out_ptr : u32` |
| `0x0004` | `out_len : u32` |
| `0x0080` | **`SRCTAB`** — `(ptr, len)` 쌍 `nsrc` 개 (gh #5 B) |
| `0x1000` | **소스가 놓이는 곳.** 호스트가 여기에 쓴다 (`compile` 의 기본 자리) |
| `0x1000 + src_len` | 힙. 프로그램이 알아서 쓴다 |
| `0x0800_0000` | **`S1`** — 힙의 천장. 힙은 여기 닿을 수 없다 |
| `0x0C00_0000` | **`S2`** — `S1..S2` (64 MiB) 는 선언 하나의 토큰, 이후 그 함수를 내보내는 동안의 본문 |
| `0x0E00_0000` | **`OUT`** — `S2..OUT` (32 MiB) 는 섹션 페이로드 하나. `OUT` 위 32 MiB 는 완성된 모듈 |
| `0x1000_0000` | **문자열 리터럴.** 컴파일러가 여기에 놓는다 (§4) |
| `0x1800_0000` | **섀도 스택 하한 (`SHADOW_FLOOR`).** 넘으면 트랩한다 (§6) |
| `0x2000_0000` | **섀도 스택 초기값 (`$sp`).** 아래로 자란다 (§6). 메모리 끝이기도 하다 |

**영역은 서로 겹치지 않아야 하고, 특히 힙이 자라는 구간(`SRC`..`S1`)에는 다른
영역이 없어야 한다.** 한동안 있었다 -- `OUT` 이 `0x0101_0000`(16.8 MiB)에 있었고
`S1` 이 8.4 MiB 이던 시절에는 `OUT` 이 힙 위였다. `S1` 을 16 배로 올리면서 `OUT` 이
힙 한가운데로 들어왔는데 아무 시험도 그것을 보지 않았다. 지금은 지도의 순서와
겹침을 `tests/test_spec_numbers.py` 가 강제한다.

### 크기 한계

메모리가 고정이므로 컴파일러가 다룰 수 있는 소스에도 한계가 있다. 아레나는 소스
뒤에서 위로 자라고 힙의 천장 `S1` 은 `0x0800_0000` 에 고정돼 있으므로,
힙이 거기 닿으면 컴파일러가 자기 메모리를 덮는다.

프로그램 전체 토큰 아레나는 없다. `S1..S2` 를 선언 하나의 토큰 작업장으로 쓰고
선언마다 되감으며, 함수 방출 때도 해당 본문만 다시 렉싱한다. 작업장이나 파싱 뒤
영구 아레나가 각자의 천장을 넘으면 `1:1` 에 진단 하나다:

```
program is too large for the compiler's memory
```

이 한계는 언어의 것이 아니라 **대상의 것**이다. 그래도 `cool0.py` 가 같은 산술로
같은 지점에서 거절한다 -- 안 그러면 큰 소스에서 두 구현이 갈리고, 그것이 §8 이
금지하는 상황이다. 공백은 더 이상 바이트마다 토큰 하나의 비용을 내지 않는다.
`cool0c.cool0` 자신은 영구 힙 천장에서 **여유 25% 이상** 떨어져 있어야 하고,
`tests/test_limits.py` 가 그것을 강제한다 -- 한때 0.7% 까지 갔고 아무도 몰랐다.

이름 ID 순서는 두 번째 순회가 소스 순서로 인턴하므로 예전과 같다. 첫 순회도 소스
끝까지 렉싱한 뒤 파싱을 시작하므로, 뒤쪽 렉스 오류가 앞쪽 파스 오류보다 먼저
보고되던 기존 최초 진단 순서도 유지된다.

이 절의 숫자들은 `tests/test_spec_numbers.py` 가 코드와 대조한다. 한때 `S1` 을
옮기고도 여기를 안 고쳐서, 이 문서를 읽고 쓴 이슈가 틀린 전제 위에 서 있었다.

문자열 리터럴 영역도 같은 성질이다. `0x1000_0000` 에서 위로 자라고 그 위가 섀도
스택 바닥(`0x1800_0000`)이므로, 넘으면 컴파일된 프로그램의 리터럴이 자기 프레임과
겹친다. `intern_string` 이 그 자리에서 막는다:

```
string literals do not fit below the shadow stack
```

```
compile(src_len: u32) -> i32      소스 하나. 호스트가 SRC 에 쓴다
compile_n(nsrc: u32) -> i32       소스 여럿 (gh #5 B)
```

- `0` — 성공. `out_ptr`/`out_len` 이 **컴파일된 wasm 바이트**를 가리킨다
- `1` — 실패. `out_ptr`/`out_len` 이 **진단 텍스트**를 가리킨다

### 소스가 여럿일 때 (gh #5 B)

`compile_n` 은 `SRCTAB`(`0x0080`)에서 `(ptr, len)` 쌍을 `nsrc` 개 읽는다. 버퍼는
어디에 있어도 되고, 힙은 그 중 가장 높은 끝 뒤에서 시작한다.

**줄 번호는 버퍼를 넘어 이어진다** — 버퍼 사이에 줄바꿈 하나를 둔 것처럼 이어
붙인 것으로 친다. 그래서 진단은 여전히 `L:C: 문구` 이고 (§9), 토큰에도 노드에도
버퍼 번호를 넣지 않는다. cool0 에는 찍을 파일 이름이 없으므로, 어느 파일인지는
각 버퍼의 길이를 아는 **호스트가** 되짚는다.

`compile(len)` 은 한 칸짜리 표를 쓰고 `compile_n(1)` 을 부르는 껍데기다 — 경로가
둘이 아니라 하나다.

렉싱과 이름 인터닝(§A)이 끝나면 컴파일러는 소스 버퍼를 **다시 읽지 않는다.**
이름은 인터닝돼 있고, 문자열 리터럴은 이미 rodata 로 복사됐고, 진단이 토큰을
묘사할 때도 인터닝된 이름이나 키워드·구두점의 철자를 쓴다. `put_src` 는 그래서
사라졌다. 이 성질이 gh #5 C 의 전제다.

cool0 프로그램의 함수는 **전부 이름 그대로 내보내진다.** 그래서 cool0 로 쓴
컴파일러가 이 ABI 를 그대로 만족한다.

## 8. 결정론

같은 입력에 대해 **같은 바이트**가 나와야 한다.

| 정해져야 하는 것 | 어디 |
|---|---|
| 명령 선택 | §5 |
| 선언 순서 | §4 — 함수 인덱스, export 순서, 타입 중복 제거 순서 |
| 리터럴 순서 | §4 — 문자열의 첫 등장 순, 주소 공유 |
| 배치와 정렬 | §2 |
| 지역변수·임시 변수 인덱스 | §4 |
| 진단 문구 | §9 |

**명세가 정하지 않은 것이 있어 패리티가 깨지면 그것은 명세의 버그다.** 참조 구현이
임시 심판이고, 결론은 이 문서로 돌아온다.

## 9. 진단

**첫 오류에서 멈춘다.** 출력은 한 줄이고 `\n` 으로 끝난다.

```
줄:칸: 문구
```

줄과 칸은 1 부터 센다. 칸은 바이트 수이며 탭도 하나로 센다. 위치는 오류가 붙는 식이나
문의 첫 토큰이다. 문구는 ASCII 소문자로 시작하는 영어 한 줄이며, 이름은 백틱으로
감싼다. 문구 하나하나가 명세의 일부다 — 두 구현이 같은 바이트를 내야 하기 때문이다.

참조 구현의 오류 목록이 그 사전이고, 패리티 테스트가 그것을 강제한다.
