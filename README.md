# coollang

**cool** 은 안전하고 단순한 시스템 프로그래밍 언어다. C 를 다시 만들되, 그 이후
40년간 밝혀진 실수들을 처음부터 피한다.

이 저장소는 아직 **cool0** 하나만 다룬다. cool0 는 cool 의 **동결된 부트스트랩
부분집합**이며, 명세는 [`src/cool0/spec/`](src/cool0/spec/) 다.

---

## cool 이 무엇을 노리는가

셋이고, 순서대로 중요하다.

**1. 확장성** — 문법이 특정 아키텍처를 가정하지 않는다. 8비트부터 64비트까지,
6502 와 PDP-11 부터 GPU 와 EVM 과 wasm 까지, 스택 머신이든 레지스터 머신이든
내려갈 수 있는 **프론트엔드**를 갖는다. 그 전부를 *지원한다*는 뜻이 아니라, 언어가
그 어느 쪽도 *막지 않는다*는 뜻이다. C 가 그랬던 것처럼.

**2. 안전성** — Rust 의 소유권을 단순화하고, Zig 의 comptime 을 매크로 대신 쓰고,
Dart 의 엄격한 null 안전성을 가져온다. 검사는 함수 하나만 보고 끝나야 한다 —
그 제약이 수명 표기를 없애고 컴파일러를 작게 유지한다.

**3. 단순함** — 키워드가 적고, 같은 일을 하는 기능이 둘이 아니다. 루프는 하나다.
`a[i] == *(a+i) == i[a]`, `int* a, b` 에서 `b` 는 포인터가 아닌 것, `p->x` 와
`(*p).x` 가 따로 있는 것 — 그런 것이 없다.

**cool 의 명세는 아직 쓰지 않는다.** "궁극의 언어"를 앞에서 설계하려는 것이
프로젝트가 멈추는 가장 흔한 방식이다. cool 은 cool1, cool2 를 거치며 자란다.

## cool0 는 무엇인가

**컴파일러를 실수 없이 손으로 구현할 수 있는 최소 언어.** 그 외의 목표는 없다.

- 타깃은 **wasm 1.0 (MVP)** 하나. WASI 도 임포트도 없다
- 컴파일러는 **순수 함수**다. 호스트가 소스 바이트를 선형 메모리에 넣고 결과
  바이트를 꺼낸다. 파일도, 경로도, I/O 오류도, 인자도 없다
- 안전 규칙은 **별칭과 가변성만**. 소유권도 수명도 자동 해제도 없다 — 컴파일러가
  한 번 돌고 끝나므로 **아무것도 해제하지 않기 때문**이다
- 소스는 ASCII 전용

명세는 **동결**이다. 부족한 것은 cool1 이 채운다.

## 부트스트랩

```
1.  src/cool0/cool0.py       참조 구현. 파이썬. 설계를 빠르게 반복하고 오라클이 된다
2.  src/cool0/cool0c.cool0   컴파일러를 cool0 로 쓴다. 1번으로 컴파일하며 개발한다
3.  src/cool0/cool0c.wat     2번을 WAT 로 옮겨 적는다. 새로 설계하는 것이 아니다
```

**3번이 독립 구현이 아니라 전사(transcription)라는 것이 핵심이다.** 함수 하나하나가
이미 검증된 cool0 코드에 대응하므로 설계 실수가 아니라 옮겨 적기 실수만 남고,
그것은 패리티 테스트가 잡는다.

고정점:

```
wat2wasm cool0c.wat   → A
A(cool0c.cool0)       → B
B(cool0c.cool0)       → C        B == C 여야 한다
```

`A` 가 `cool0c.cool0` 의 충실한 전사라면 `A` 와 `B` 가 같은 코드를 뱉으므로 `B == C`
가 바로 나온다. 어긋나면 전사가 틀린 것이다.

### 신뢰 사슬

```
wat2wasm  +  wasm 런타임        ← 믿는 것 전부
```

**`cool0.py` 는 사슬에 없다.** 오라클이다 — "WAT 판이 맞나"를 묻는 도구이지 wasm 을
만드는 물건이 아니다.

## 검증

컴파일러가 순수 함수라 출력이 그냥 바이트다. 그래서 검사가 바이트 비교다.

```
cool0.py(src)      → (status, bytes)
cool0c.wasm(src)   → (status, bytes)      완전히 같아야 한다
```

**바이트 단위 동일**이 목표다. 최적화가 없어 코드 생성이 문법 지향적이므로 달성
가능하고, 무엇보다 **명세가 완전한지 검사하는 장치**가 된다 — 애매하게 남은 곳은
패리티가 깨져서 바로 드러난다.

퍼징은 세 층이다.

| | |
|---|---|
| 랜덤 바이트 | 렉서와 오류 경로. 크래시하지 않는지 |
| 문법 기반 랜덤 프로그램 | 파서·타입 검사·코드 생성 |
| 의미가 있는 랜덤 프로그램 | wasmtime 으로 돌려 결과까지 비교 |

## 작업 순서

**단계마다 파이썬과 WAT 를 같이 올린다.** 파이썬을 다 쓰고 WAT 를 시작하지 않는다 —
이 계획의 유일한 실질 위험이 *파이썬 판이 진짜 구현이 되고 WAT 판이 영영 안 끝나는
것*이고, 단계별 패리티가 그것을 막는다.

```
렉서       py → wat → 패리티 통과
파서       py → wat → 패리티 통과
타입 검사  py → wat → 패리티 통과
방출       py → wat → 패리티 통과
```

## 왜 wasm 인가

부트스트랩 타깃으로 고른 이유는 이식성만이 아니다.

**wasm 은 구조적 제어 흐름을 갖는다** — `block`/`loop`/`if`/`end`. 이것이 재귀 하강
파서의 재귀 구조와 정확히 일치해서, **점프 대상 백패치가 통째로 사라진다.** 손으로
쓰는 컴파일러에서 가장 버그가 잦은 부분 하나가 없어지는 것이다.

그리고 오브젝트 포맷도, 링커도, 호출 규약도, 레지스터 할당도 없다.

## 정해진 것들과 그 이유

다시 논의하지 않기 위해 적어 둔다.

| | |
|---|---|
| cool0 에 소유권이 없다 | 순수 함수라 해제할 것이 없다. 그리고 **cool 의 안전성은 cool0 가 안전한지가 아니라 cool1 의 검사기가 옳은지에 달려 있다** |
| 대여는 호출 인자 자리에서만 | 그러면 대여가 호출과 함께 죽으므로, 별칭 검사가 "한 인자 목록에 같은 변수가 두 번, 하나가 `&mut`" 하나로 끝난다. 수명 분석이 없다 |
| enum + match 는 넣는다 | `cool1c.cool0` 도 cool0 로 쓴다. 타입 검사기는 합 타입 덩어리고, 배리언트를 추가할 때 **완전성 검사가 고칠 곳을 전부 알려주는 것**이 값을 한다 |
| 기본 불변, `mut` 으로 연다 | `let`/`&`/`[]` 에 규칙 하나가 똑같이 적용된다. `const` 수식어를 따로 두지 않는 이유 |
| 집합체를 값으로 전달하지 않는다 | 복사 코드 생성이 사라진다. `&T` 로 넘기거나 슬라이스에 담는다 |
| `match` 는 문이다 | 값을 만들면 결과 타입 통일 규칙이 붙는다. cool1 에서 열면 된다 |
| 파이썬 참조 구현을 둔다 | 병목은 크기가 아니라 **정확성**이다. 오라클이 그것을 직접 친다 |
